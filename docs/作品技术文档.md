# 项目概述

观动知姿是一款面向自主健身场景的AI Web应用。使用者通过浏览器采集训练画面，或上传已经录制的训练视频，系统将人体姿态、动作过程、问题时间段和调整建议呈现在同一条操作路径中，并支持训练记录、历史回看、AI解读和报告导出。

自主训练时，使用者需要回答三个具体问题：动作过程中出现了什么变化、变化发生在什么时候、下一次练习如何调整。传统视频回放需要反复拖动和比对，零散的训练记录又难以与画面对应。本项目以画面和时间段为中心，将姿态观察、连续规则和个人训练数据结合起来，形成“采集—分析—定位—理解—回看”的产品闭环。

## 作品定位

项目采用Web形态，将视觉分析、前端交互和AI解释组织为一体。摄像头与视频文件由浏览器接入；视觉关键点与运动规则在本地服务中处理；前端呈现处理状态、骨架和问题定位；AI服务根据已保存训练证据生成解释与复盘。

## 产品价值

对训练者，系统把抽象的姿态提示转化为可定位、可回看的画面信息。对校园健身社团和运动兴趣小组，系统提供统一的记录与反馈入口。对教学演示，系统可以展示人体关键点、动作阶段和规则判断如何共同生成运动指导。

## 核心特点

| 设计特点 | 作品实现 |
| --- | --- |
| 画面与反馈对应 | 保存问题时间段，支持定位回看 |
| 连续运动观察 | 按时间窗、动作阶段和关节可见性生成提示 |
| 统一Web工作流 | 实时分析、视频分析、记录、设置和AI解读共用界面体系 |
| 证据驱动的AI解释 | 将当前训练记录、问题和来源版本绑定到AI上下文 |
| 可复现的评审环境 | 提供运行脚本、依赖锁定、模型摘要和公开演示素材 |

# 需求分析

## 面向的使用者

主要使用者是具有自主训练需求的高校学生与健身爱好者。他们能够使用手机或电脑记录训练，但希望用更少的操作找到动作中的具体变化。系统围绕训练前的准备、训练中的观察和训练后的复盘安排功能。

训练前，使用者需要选择输入来源、动作与机位，确认相关身体部位能够进入画面。训练中，使用者需要简短而明确的状态反馈。训练后，使用者需要查看具体问题、对应时间、调整建议及历史记录。

## 典型使用流程

1. 使用者登录，进入实时分析或视频分析。
2. 根据取景提示准备画面，按需选择动作和机位。
3. 系统接入画面，完成主体与可见性检查，连续观察动作过程。
4. 视频任务展示进度；处理过程中统一显示“正在观察”。
5. 分析完成后，界面按问题展示时间段与建议，使用者点击“定位片段”回看。
6. 使用者保存训练信息，并通过AI解读或报告进一步理解本次训练。

## 功能需求

输入层支持摄像头和视频文件。分析层提供人体姿态、动作周期与连续质量观察。交互层提供骨架绘制、观察状态、问题列表和时间定位。数据层支持账号、训练档案、训练记录、备注与报告。AI层提供围绕当前训练事实的对话和复盘。

## 交互质量需求

界面需要在桌面和手机上保持清楚的层次。耗时的视频处理应持续显示进度；保存和处理分别确认；离开、取消、恢复和刷新具有可理解的结果。敏感配置集中于设置，主要训练页面保留与当前任务直接相关的信息。

# 系统架构设计

系统采用浏览器与本地服务协作的架构。浏览器负责媒体交互和可视化，本地服务负责输入处理、视觉计算、任务编排与持久化，AI接入层负责训练证据组织和模型请求。

@diagram architecture

## 前端呈现层

页面由HTML、CSS和JavaScript ES模块组成，Jinja模板提供统一页面骨架。Canvas负责关键点和连线绘制，浏览器媒体接口负责摄像头与视频播放。实时页面、视频页面和记录页面通过各自模块管理状态，共享提示、请求和来源校验逻辑。

## 分析与任务层

Flask提供页面和API，Waitress提供本机HTTP服务。输入服务处理视频校验和临时副本；实时会话服务负责画面接入和训练状态；视频任务服务负责有界解码、进度、取消、保存与收尾。连续规则引擎与完成量观察分别消费姿态信息。

## 数据与AI层

SQLAlchemy与SQLite保存账号、会话、动作事件、姿态观察及AI请求。AI服务在请求前读取当前有效记录，组织来源、时间范围和问题证据；响应按流式方式呈现，并与所引用记录保持关联。

## 模块边界

系统将媒体来源、人体定位、动作阶段、姿态指导、页面展示和AI解读分开管理。每一层使用明确的输入与输出结构，便于定位问题、复用能力和检查数据是否仍与当前画面对应。

# AI视觉输入方案

## 本地姿态关键点

系统使用MediaPipe Pose Landmarker作为基础人体姿态输入，获取图像坐标、关节可见性与人体空间关系。输入适配层保留原画面的尺寸和时间戳，并在裁剪处理后将关键点映射回原图坐标，供骨架绘制与连续分析共同使用。

OpenMMLab RTMPose和RTMDet ONNX资源提供独立的身体与手部观测。资源清单记录固定版本、文件大小与SHA256。运行时先检查资源身份，再将观测交给相应规则，形成从模型文件到界面提示的可追溯链路。

## 图像坐标与主体一致性

模型输入处理会检查画面边界、人体数量、关键部位可见性及主体连续性。裁剪、缩放与填充均保留映射信息；骨架在原图坐标中绘制，使页面连线与训练者画面保持对应。

连续分析以当前主体为对象。模型观测、身体关键点和手部候选通过空间关联进入规则，使动作期间的观察能够沿用同一主体、同一侧别和同一时间基准。

## 适用机位与输入准备

不同动作使用不同的观察部位和推荐机位。例如，躯干与髋部关系需要肩、髋等核心关节可见；手臂动作需要同侧肩、肘、腕连续进入画面。页面把这些要求放在开始分析之前，让使用者先建立适合观察的输入条件。

## 模型与规则协作

视觉模型提供身体结构和运动信息，连续规则将这些信息转化为具体观察项目。系统根据角度、相对位移、时间窗和动作阶段组织证据，再生成问题名称、建议和时间范围。这样的分工让视觉能力与运动过程的解释相互衔接。

# 连续运动指导方案

## 从单帧关系到连续过程

运动指导围绕一段动作过程展开。规则引擎保存有限时间窗中的有效观测，结合关节方向、相对位移和阶段变化判断当前项目。时间中断、画面变化和主体变化会进入相应的状态处理，当前结果随证据更新。

| 观察项目 | 主要输入 | 连续判定思路 |
| --- | --- | --- |
| 身体侧倾 | 肩髋关系、躯干中线、场景参考方向 | 在连续窗口中核对方向与持续性 |
| 双侧阶段同步 | 左右关节的归一化运动曲线 | 比较两侧阶段延迟及曲线一致性 |
| 肘部稳定 | 同侧肩、肘、髋与躯干尺度 | 观察肘部相对躯干的位置变化 |
| 回程节奏 | 动作阶段、往返幅度和源时间戳 | 对比用力阶段与返回阶段的时长 |
| 可见手腕方向 | 前臂、手腕与掌骨关键点 | 在同侧关联后观察方向偏折 |

## 身体侧倾观察

身体侧倾模块将躯干和肩线与画面参考方向共同考虑。场景方向由独立的背景信息估计，身体姿态由关键点描述，连续窗口检查方向是否一致。输出包含侧别、时间段和身体部位，便于界面给出具体提示。

## 阶段与相对坐标

回程节奏依据动作的用力与返回阶段组织，而不是仅依据某一帧的速度。肘部位置以同侧肩髋建立的局部坐标和躯干尺度描述，使身体整体移动与局部姿态变化能够分别处理。

## 指导结果结构

每条结果包含规则编号、状态、来源版本、开始时间、结束时间、侧别、问题部位、描述和建议。系统据此完成保存、主要提示选择、骨架部位标识与历史回看，保持不同页面对同一条结果的解释一致。

# 视频分析与问题定位

视频分析以任务形式运行。视频通过编码、方向、时间戳和首帧等检查后，系统按原视频时间有界解码，逐步完成姿态观察并保存结果。页面同时显示已处理时间和任务状态。

## 分析过程

使用者点击开始后进入“正在分析视频”页面。画面跟随已处理的源时间，骨架与该帧对应；提示区统一显示“正在观察”。取消、保存和完成各有独立状态，页面刷新后能够重新查询同一任务。

## 完成反馈

分析完成后，页面展示本次保存的问题名称、具体时间段和调整建议。使用者点击“定位片段”，视频跳到问题开始位置；拖动到其他时间时，提示依据该时刻对应的结果更新。

@image 视频分析.png 公开示例视频的真实本地分析结果与时间定位界面

## 数据一致性

问题的时间基准与原视频一致。页面通过来源摘要和素材身份核对视频，已保存摘要与播放来源匹配后再组织回看。原视频处理、任务进度、保存量和临时副本收尾分别记录，确保使用者理解当前任务所处阶段。

# 实时分析与统一交互

实时分析将取景、动作设置、观察提示和训练操作放在同一工作区。使用者按需选择动作及机位，再开启摄像头。浏览器采集画面，本地服务完成观察，前端使用同帧结果绘制骨架和当前提示。

## 统一的反馈语言

系统明确区分正在观察、具体问题、已检查项目的结果及保存状态。观察中的页面保持简短；形成具体问题时给出可执行的建议；训练后的页面提供时间段与回看入口。状态文案与实际处理阶段相对应。

## 桌面与移动端

导航、按钮尺寸、设置入口和页面层次保持一致。手机布局根据可用宽度调整，重点保留画面、当前状态和主要操作；个人配置集中到设置页面。训练相关页面采用响应式布局，共用同一套功能和数据。

@image 首页.png 首页中的公开演示视频与同步骨架展示

## 媒体生命周期

摄像头开启、暂停、结束与页面离开都有对应的释放与恢复逻辑。播放器拖动、暂停和刷新也会触发状态更新，使当前画面与提示同步。对于耗时操作，按钮及时给出处理中状态，并保留返回和查询任务的路径。

# AI训练解读方案

AI模块将训练数据转化为更容易理解的说明。使用者可以围绕当前训练提问、查看整次训练复盘，或在可比较的记录之间生成前后对比。AI上下文从当前有效的训练记录和问题观察中组织，而不是仅依赖一段自由文本。

## 证据组织

服务端在发起请求时绑定记录来源、时间范围和版本，向AI提供已保存的动作事件、姿态结果及训练档案。对话中可以引用当前画面和记录摘要，帮助解释具体问题。来源修订与结果有效性使用独立状态管理。

## 对话与复盘

前端采用流式输出呈现解读内容，使用者能够看到生成进度。复盘按记录范围组织内容；前后对比使用对应时间和相同观察项目；历史解读保留其来源信息，便于回看当时的训练背景。

## 服务端密钥与费用控制

系统支持个人密钥和系统体验来源。密钥在服务端加密保存；页面只显示必要的配置状态。请求前检查使用来源、输出限制及额度，响应后记录用量。密钥管理、连接检查和训练对话分别处理，使配置操作与实际生成调用保持清楚的边界。

## 视觉与语言协同

视觉分析负责产生结构化的动作和姿态观察，语言模型负责解释这些观察、组织复盘和回答相关问题。两类能力通过训练证据连接，使AI交互成为运动指导工作流的一部分。

# 训练数据与账号设计

## 训练记录

训练记录围绕会话组织，包括训练来源、动作、组次、完成量、时间、姿态观察、备注与训练档案。视频任务和摄像头训练共享相同的数据语义，并保留各自的来源信息。

SQLAlchemy负责数据访问，SQLite负责本地持久化。保存链按照明确的会话和事件身份写入，重试围绕原请求和原批次进行，页面分别展示处理进度与保存结果。

## 个人信息与设置

个人中心提供记录和训练资料入口；设置集中管理密码、AI密钥和登录相关配置。用户请求在服务端核对身份和记录归属，读取、修改和删除均围绕本人数据进行。

## 骨架与报告

系统支持按使用者选择保存骨架，并在来源匹配后进行轨迹回看。记录摘要与骨架资源采用独立生命周期，报告按当前记录快照生成，便于保存和分享结构化训练结果。

## 评审环境隔离

比赛仓库使用公开示例素材和独立初始化的数据环境。首次启动由操作者创建本人管理员，应用在本地生成数据库和认证文件。运行配置、上传资料、模型文件和源代码按目录与用途分开管理，版本控制只纳入交付所需内容。

# 测试与工程验证

测试围绕规则行为、状态转移、数据保存与真实页面交互展开。工程输入用于检验边界与控制逻辑，公开原视频用于检验真实视觉输入与完整任务链，浏览器用于核对用户实际操作。

| 验证层次 | 检查内容 | 对应证据 |
| --- | --- | --- |
| 连续规则 | 时间窗、侧别、动作阶段、可见性与恢复 | Python规则测试 |
| 指导状态 | 观察、问题、暂停、保存和终态 | 指导与保存链测试 |

## 可重复的检查方式

仓库提供规则、指导与界面提示测试，依赖清单锁定运行环境。模型资源准备工具可以离线核对已经存在的文件，也可以从固定来源恢复所需资源。资源身份与参数身份共同参与运行校验，使相同代码和相同输入具有可追踪的执行依据。

## 公开原视频运行

交付验证使用公开DVIDS杠铃划船视频，在独立账号和独立数据库中完成解码、真实姿态模型推理、连续观察和任务保存。首页演示与重新分析使用同一登记来源，记录按演示类型组织，个人训练统计保持清楚的来源分类。

## 界面检查

桌面与手机宽度下分别检查页面状态、画面显示和操作入口。处理中提示与最终问题列表使用不同阶段的呈现方式；定位与拖动均依据源时间更新。实际检查记录随仓库保存在交付核验文件中。

# 安装运行与资源管理

## 评审运行环境

项目提供Windows启动脚本和Python依赖锁定文件。CPU姿态评审配置使用Python 3.12、MediaPipe、ONNX Runtime、Flask与SQLite；前端在现代桌面或手机浏览器中运行。Node.js用于界面提示模块的工程测试。

## 运行步骤

1. 在可写目录获取仓库，使用PowerShell运行环境准备脚本。
2. 安装锁定依赖，恢复并校验CPU姿态评审资源。
3. 运行管理员初始化命令，由操作者创建本人账号。
4. 启动本机服务，浏览器打开回环地址并登录。
5. 依次体验公开演示、视频分析、实时分析、记录与报告。
6. 需要AI解读时，在设置页面配置使用者自己的服务密钥。

## 资源与目录

运行工具将依赖、缓存和任务数据放在仓库自己的目录内。模型资源清单保存固定地址、版本、大小和摘要；已有资源核对通过后直接复用。中文字体和第三方许可随交付代码保留。

扩展视频语义配置由独立的模型清单和依赖文件组织，可按相应硬件环境恢复。系统将模型资源、运行配置与个人数据分开管理，便于复现、评审和后续维护。

## 本地与Web访问

当前启动器提供本机回环服务，适合桌面评审与开发演示。Web呈现层与服务端媒体接口分开，手机浏览器使用相同页面体系。应用可以按实际展示环境配置受信访问来源，使部署边界与媒体权限保持一致。

# 技术创新与应用价值

## 将运动过程转化为可定位的信息

项目把姿态提示从一个短暂状态扩展为具有时间范围、侧别、部位和来源的结构化结果。使用者能够从问题列表直接回到画面，观察同一时间发生的身体变化，降低反复寻找视频片段的操作成本。

## 视觉输入与连续规则协同

视觉模型提供身体结构，连续规则提供动作过程的组织方式。项目围绕阶段、相对坐标、方向一致性和时间窗设计观察项目，将不同模型的输入与统一结果结构连接起来。

## 围绕训练证据组织AI解释

AI交互与训练记录绑定，解读范围具有明确来源。项目通过记录版本、时间范围、问题事实和训练档案组织上下文，使对话、复盘与回看连接在同一条数据链中。

## 前端与工程状态统一

项目将观察、处理、保存、完成和回看分别设计为清楚的页面状态。耗时任务具有持续进度，结果具有定位入口，配置集中管理，桌面与手机沿用一致的操作语言。

## 开源能力的工程化整合

项目保留预训练模型、参考算法、开发框架和字体的来源与许可，将它们整合到自有的媒体输入、任务、权限、保存和前端工作流中。资源校验与可复现脚本使整合过程可以被检查和重新执行。

## 应用价值

作品适用于高校自主训练、社团交流和运动技术可视化展示。以可见画面和训练记录为共同入口，系统帮助使用者把一次训练转化为能够查看、定位、解释和回顾的信息，体现AI技术与Web交互结合的实际价值。
