# 步骤33：组内运动稳定性观察

状态（2026-10-24）：已实现默认训练摘要中的组内运动观察、自动/固定/上传三条采集链、本人记录与AI引用、手机前后值/区间图和明确不可比状态。23个相关后端专项及手机页面检查分别通过；真实短片缓存回放均未满足前后比较，不制造“更稳/改善”。本步不代表独立姿态纠错精度或33类识别门槛通过。范围引用[R3-10](../第三轮优化/问题与优化方案.md#round3-scope)、[取景/复测/稳定性规范](../第三轮优化/开发与验收.md#4-取景复测稳定性与骨架)。

## 产品行为

记录详情新增浅色“组内运动观察”。同组、同输入连续段和同类观测下，展示前后中位值、有效/未知样本、原始范围和简短变化说明；更多项目及统计口径放在展开区。仅用户展开时读取已保存区间绘图，选择项目后可看实际统计点；未知、机位/尺度变化处断开连线，图不是人体轨迹，也不补造观察。

“后半段增大/减小”只指所选图像测量值，不等于动作变好/变差；“没有明确变化”不等于动作标准。无足够观察、机位变化、尺度变化、策略不支持或旧记录未采集均有明确说明，不显示零分、健康评分或肌肉疲劳。默认主画面仍用于实时姿态反馈，不增加计时/次数仪表盘或第五项导航。

摘要不依赖“保存骨架复盘”开关。新增记录只保存业务需要的标量区间统计，采样中的坐标立即转换为角度/距离比例，额外的关节轨迹不落盘。骨架及其30天/提前删除仍按[步骤32](32_可选骨架保存与复盘.md)独立处理；删除骨架不删除普通训练摘要，删除整条记录则级联删除本步统计。旧记录没有这些数据时不自动补算或重新推理。

## 指标和可比条件

策略`movement-stability-1`，不会修改原姿态阈值或分类权重。`movement_stability.py`配置对应动作的可观测量，而非给所有动作强套同一评分：

| 输入/动作 | 保存的观察 | 边界 |
| --- | --- | --- |
| 深蹲、后撤弓步 | 完整周期中的膝部图像角度范围 | 使用相应侧面/斜侧面规则，分侧动作不把另一侧周期算作缺失 |
| 俯卧撑、站姿弯举 | 周期中的肘部图像角度范围 | 对齐完整周期、侧别及规定机位 |
| 硬拉 | 周期中髋、膝图像角度范围 | 不判断脊柱局部曲度、受力或实际重量 |
| 杠铃划船 | 周期中的躯干图像方向变化范围 | 只报告投影变化，不把角度当腰椎曲度 |
| 臀桥、仰卧起坐、高抬腿 | 已产生的参考运动区间中的髋部角度范围 | 参考区间与已开放计数的周期分开，不输出已验证次数 |
| 开合跳 | 周期内上臂图像活动范围 | 正面观察，不将膝部屈伸当成此动作的开合幅度 |
| 平板支撑 | 髋与肩踝连线的图像偏离 | 侧面且支撑/判项可评估；支持不足的帧降低覆盖 |
| 杠铃肩推与21项健身房动作 | 等长窗内躯干图像方向变化范围；适合双侧同时动作的类别另有正面左右腕高度差 | 弯举等可能交替的类别不机械套用双侧同步指标；腕高度差为绝对差，不提供哪侧更高 |

几何数据是二维图像角度/归一化比例。比例以画面中的躯干投影长度为1，不是实际人体尺寸。每侧使用清楚可见的关节、单人连续目标；不以隐藏关节插值。仅保留标量序列在内存中最多31秒、至少50ms采样间隔，之后保留区间统计，不存RGB、声音或关节坐标。

连续观察使用非重叠3000ms窗口，至少8个有效采样、有效时间覆盖至少80%、相邻有效间隔不超过500ms；无效采样会截断覆盖，不跨缺失连接。动态上肢还需可见角度变化，准备静止不作运动稳定性结论；平板须有可评估支撑证据。计数器的参考完整周期、非计数参考区间、等长窗分组统计，互不换算。未满窗尾段明确排除，不补成完整窗口。

每组/输入连续段内，前后各至少3个有效同类样本，每半有效样本覆盖至少80%。不同侧别、周期/区间类别、规则/姿态模型、机位或声明来源不混合；显示比例改变、窗内尺度突变，或前后投影尺度比超过1.25均拒比。暂停/换流、分组、自动切动作及源片剪接分别隔开。左右交替动作按各自侧别比较，不要求另一侧动作时同时评估本侧。

范围量用P90−P10，偏离/左右差用中位值；前后再比较中位值和中位绝对偏差，同时保留区间原测量极值及样本值范围。变化须超过工程噪声带（角度3°/比例0.03与前后离散度取更大值）才标方向；它不是健身标准或显著性检验。周期覆盖仅指已经形成的参考观测，不证明整组每个动作都识别成功。

## 保存与接口

schema10新增`stability_runs/stability_windows`，通过本人训练记录级联归属。每记录最多1000个观察摘要、每个JSON不超过32KiB，顺序唯一索引与内容SHA确保同批重放不重复。形成正式记录前最多暂存30个窗口，超限保留已收集前缀并提示；正式记录中达到上限也不覆盖旧数据。保存故障停止新增运动摘要，保留已写入部分，主要训练摘要按原流程处理。

三条链路均在正常记录中绑定本步策略：自动识别在原动作段内采集，固定训练保存已提交事件后采集，并保留组与单调记录时间，上传按每个原视频动作片段/修订保存。原请求幂等摘要不因新增服务端策略标记而改变。服务重启及结束未确认标中断，保留已有窗口，不重跑模型补齐。

`GET /api/v1/records/<id>/stability`读取本人已保存摘要，`?windows=1`才附实际窗口；普通记录DTO增加`movement_stability`。运行保存状态与是否足够比较分开，complete不能解释为动作合格。无数据返回not_recorded/insufficient_evidence，策略不认识时不以当前算法重新解释旧数据。损坏返回明确状态，训练记录主DTO仍可查看，不能因为附加统计损坏就隐藏原训练摘要。

账号隔离、版本/幂等、删除级联及关键索引/外键校验已接入。正常追加只产生不可变摘要；不对外开放客户端自报测量或任意用户ID。普通业务摘要随训练记录保留，不沿用可选原始骨架的30天期限。

## AI依据

AI读取本人的已保存运动摘要并显示实际读取数量；`m:`证据明确为观测，状态observation不是姿态issue。数值仍由应用展示，AI自由文字不重写测量值。引用必须存在，不得把变化转成技术正误、疲劳、发力、伤病风险、因果改善，也不能根据绝对左右差猜哪侧更高或根据范围猜向哪边偏。解释、摘要和重点均有对应检查；建议来源为measurement_reference，不能冒充登记的纠错规则。当前提示策略`grounded-coaching-7`；整条记录删除后旧AI依赖失效。其他AI费用/权限及实时冻结时刻引用[步骤25](25_DeepSeek配置与证据问答.md)、[步骤30](30_AI提问时刻与实时画面隔离.md)。

## 已执行验证

新增专项共22项：纯统计12项，持久化/权限/AI/策略7项，自动/固定/上传集成3项；另仅重跑受schema目标变化影响的原schema8迁移用例1项，共23个相关后端检查通过。包括未知/静止不当稳定、尺度/机位/模型/显示比例拒比、分组/分流/分侧隔离、异常值保留而不制造趋势、非计数区间不混周期、平板覆盖、未知参考区间保留、默认无需骨架保存、上限前缀/失败不阻断主摘要、私有访问/删除级联、策略/损坏不伪成功、9→10迁移原子回滚与关键索引拒绝，以及AI错误因果/方位杜撰拒绝。

`stability_ui_check.mjs`通过实际记录API下的前后卡片、原范围、已保存区间图、刷新重读、旧记录无数据、320/390布局及无相机调用；卡片简化后只复核layout范围。[手机实际渲染](../data/verification/round3/movement-stability-mobile.png)已查看，统计来自合成工程输入，不是真人效果证明。

`verify_movement_stability.py`只读取已校验的[真实组合源清单](../data/verification/round3/upload-real-source.json)与原数值姿态缓存；按每个来源剪接片隔开，动作来自已知源标记，不声称重新自动识别。肩推形成2个窗口，划船1个区间、两段硬拉各1个周期，均未满足前后比较，没有输出更稳/改善。结果、源/缓存/当前策略代码SHA在[真实缓存回放](../data/verification/round3/movement-stability-real-replay.json)；新增姿态推理、分类调用、付费AI均为0。准备背景未被当作动作稳定性样本，旧GPU矩阵没有重跑。

所有测试库、浏览器配置、服务均在项目内隔离，已关闭清理。没有现场相机、个人库迁移或真实AI收费。33类逐类识别/具体纠错、实机/HTTPS、长时性能及第三轮其他未完项继续验收，本步不代表整个项目完成。
