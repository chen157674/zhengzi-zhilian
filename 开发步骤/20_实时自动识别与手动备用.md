# 20 实时自动识别与手动备用

状态：12类自动判断路径已补齐并接入基础后端。用户明确“基本实现”仍须覆盖全部12类，不能将3类留为手动专用。现采用已训练图像／骨架模型加连续姿态模式；全部12类有实际分类与分析路由，独立真实准确性仍未完成。2026-10-22前端自动入口与显式训练分段保存已在[步骤21](21_新前端按图实现与闭环.md)接通，纯预览仍为内存结果。下文保留开发历史，当前范围以末尾“十二类实现补齐”为准。

## 需求与衔接

依据[PRD最新实时要求](../PRD.md)、[开发文档自动识别接续](../开发文档.md#automatic-exercise-recognition)。复用07的图像处理／鉴权／独占槽，08的控制与身份连续性，12／14的分析器，15～17的纠错与06的保存恢复。不重新要求用户决定自动还是手动的默认优先级。

1. 自动观察无需action_id；手动备用仍可显式指定动作和能力版本。
2. 基于连续运动识别动作，加入未知、静止、过渡、遮挡与多人拒判；动作识别和姿态正确性分别输出。
3. 稳定确认后启动对应分析器；动作变化时先停止旧指导／未完成周期，再确认新动作，不能逐帧换类。
4. 将自动监测按动作切分为有归属、有模型版本的记录段，不改写原单动作历史；暂停、结束、失败恢复与目标计数分开处理。
5. 验证真实自动识别、切换、纠错和保存链，以及手动备用；只补新增或受影响用例。未知类别与原12动作完整范围均须验，不能以四分类结果代替。

## 已完成的首批实现

- `POST /api/v1/previews`省略动作时默认auto；指定`recognition_mode=manual`并提供动作进入备用路径。旧客户端已有明确action_id且无mode时保留manual兼容。auto同时提交动作／能力版本返回422，不让预选动作冒充自动识别。
- `GET /api/v1/recognition`返回默认／备用模式、模型可用性和范围；当前自动训练记录可用性及12类完整支持均为false。
- 自动观察调用共同身体有效性检查和新`ActionRecognizer`，不预先运行某个动作的计数器。结果返回确认状态、候选／已确认动作、树投票分数、不可用原因及手动备用标志；分数不称校准概率。当前模型未过线，因此正式返回自动暂不可用，不输出已确认动作。
- 观察窗口最多240帧／最近2秒，最多每250ms分类一次，同一候选持续750ms才确认。未知、目标丢失、源时间缺口清空确认；结果超过1秒不再提示已识别。关闭清除识别器，保留原预览租约、帧鉴权和所有者边界。
- 首批自动预览仅观察；本轮已接对应分析器、指导及骨架提示，但仍不保存训练成果，旧手动会话移交接口拒绝把预览冒充自动训练记录。手动完整链继续可用，自动分段保存仍待实现。前端未改。

## 十二类实现补齐

用户纠正：全部12动作均须判断是什么动作，“基本”不意味着减少类别。原4＋5＋3发布范围撤销，前三个无学习模型类别改为连续运动规则自动判断；已有9类保留图像模型并补运动模式。`motion_recognition.py`输出由真实关节点时间序列计算，未读入动作名／预选动作，也未把测试指定标签当分类结果。

| 动作 | 新增的连续模式判别依据 |
| --- | --- |
| 深蹲 | 双膝同步屈伸、双脚间距稳定 |
| 俯卧撑 | 俯撑身体线、手脚支撑位置、屈肘再伸展；排除单向进入平板 |
| 后撤弓步 | 双脚分离、身体下降与脚朝向支持的后撤；前迈不直接算后撤 |
| 双脚臀桥 | 仰卧屈膝、肩部相对稳定、髋部升降 |
| 屈膝仰卧起坐 | 屈膝仰卧、髋部相对稳定、上身明显抬起 |
| 前臂平板 | 俯撑身体线、屈肘支撑与持续稳定 |
| 开合跳 | 双臂上举与双脚开合共同发生，不把肘弯曲当成另一个动作 |
| 原地高抬腿 | 双膝及脚交替上抬，身体水平位移较小 |
| 站姿弯举 | 上臂／躯干和下肢相对稳定、肘反复屈伸 |
| 杠铃肩推 | 躯干直立、上臂上举、手腕达到肩上方 |
| 杠铃划船 | 俯身与屈肘拉动，手腕远离地面支撑区；允许一定躯干晃动 |
| 传统硬拉 | 髋部与躯干起落、手臂大致伸直，区别于主要屈肘拉动 |

以上为项目12种动作的参考运动模式；器械／细分变式仍是自动推断，不宣称仅凭骨架测出了杠铃或肌肉发力。多条模式同时满足、图像与姿态明显冲突、多人、缺点／时间缺口仍可拒判。未训练3类不再被9类分类器的标签空间否决。接口区分12类实现覆盖与独立准确性，反馈保留判别来源，纯姿态规则没有虚构分类概率。
