# 65 身体侧倾参照修复与纠错能力核查

2026-10-29。用户要求继续优化身体倾斜漏检，并明确解释当前实际能纠错什么。本步沿第三轮执行，先登记方案再实施；本机处理私人素材，复用已有RTMPose权重，不调用收费API、不重训识别模型、不改原视频/标注。

## 1. 已确认问题

步骤64的身体指标以骨盆为方向参考，身体和骨盆一起倾斜时会相互抵消。旧背景方向使用整个人体外接矩形遮罩与全局平行线共识，容易排除可用器械立柱，也未充分处理透视。原12度阈值与新8度相对角度均未命中1693/1694。不能把无提示说成姿态正常。

当前正式代码共53个参考判项、覆盖33动作，主要是幅度、躯干摆动、双臂高度、上臂摆动、平板髋位与硬拉伸展。条目覆盖不等于独立纠错准确性已通过；步骤55/58仍有真实漏检。三RF预训练偏差分类、SiTrEx相似性、MMPose手指观察属于默认关闭的候选，不能列作网站已经可靠支持的握法纠错。

## 2. 实施顺序

1. 复用原图与已有RTMPose身体点，检查画面竖向、双肩连线及肩髋中线；不再用骨盆方向抵消整体倾斜。
2. 独立实现局部画面方向参考：在人体骨段/躯干区域外提取分布足够的长线，比较平行/透视模型，评估主体附近方向及残差。方向证据不足或相互冲突时拒判，不默认图像边缘就是重力，不用人物肩髋反过来确定相机方向。
3. 使用相对该独立方向的肩线倾斜与躯干中线偏移共同确认。初始开发参考为两项同方向、各至少3度、平均至少6度；连续时间窗至少900ms、有效支持至少80%，允许窗口内少量低于确认带的抖动，但当前缺点/缺方向立即撤回。阈值是工程参考，不宣称医学或专家安全标准；在整段回放前固定，不按视频编号输出或特殊处理。
4. 补相机旋转后直立不误报、整体侧倾可检出、单肩抬高与身体侧倾区分、遮挡/旧帧/多人拒判及恢复、持续同向与短瞬态的测试。背景参考自身加入透视、倾斜相机和无证据反例。
5. 用1693/1694、1692及1575的完整原视频跑真实输入与原身份门控，保存逐帧角度、方向来源、参考质量、确认区间、截图及失败。1575可作身体投影额外对照，不据不同动作给握持真值；同人材料仍只算开发验证。
6. 如身体侧倾确有改善，将其独立接入可见反馈、部位高亮与本人保存，验证真实路径；手部未解决部分继续标明边界，不借身体改善宣称握法完成。候选启用依据真实效果与误报检查，不能因测试通过就开启全部预训练规则。
7. 同步本文件、README、第三轮PRD与验收；简明列出已接入/有真实命中/仍未可靠识别的能力。保留旧失败证据，清理本次归属明确的临时项；步骤64已被自动审批拦截的历史残留不换方法删除。

## 3. 阶段排查记录

首轮新测量已做858帧回放，仍未确认问题：1694仅12帧取得瞬时场景参考，无法满足连续条件。失败汇总保留在`body-lean-review.json`的历史结果。进一步发现原RTMPose把完整宽画面用作人体框，需改用原唯一人体的自动框提高输入分辨率；背景方向需以人体之外的特征点/KLT与RANSAC仿射跟踪传递，不能因单帧长线暂缺而丢弃已可靠取得的方向。新参考必须由图像证据初始化，跟踪点/内点比例/分布/时间间隔不足立即拒判，并设置参考重新校准时间，不能永久缓存方向或用人体侧倾反推相机。

自动人体框和背景跟踪后，1694已出现72个issue采样，1693有短段单帧超过参考带却仍未形成确认。时间窗改为对两项角度分别取中位数，要求至少80%帧具有同方向可靠观测，再比较各≥3度、平均≥6度；已确认后使用4度恢复带抑制边界抖动。不是要求80%单帧都严格超过6度，缺点/缺参考的当前帧仍立即撤回。1692也出现23个issue采样，但该片没有独立正常真值，需单列人工复核，不能算正确命中。

上述为排查期间的改进过程；最终交付和实际回放结果见第4节，不把局部改善视为纠错准确率达标。

另补一条必要边界：躯干侧倾时，人可以有意保持双肩水平，不能把肩线也倾斜设为唯一前提。第二条证据路径使用同一帧原MediaPipe与RTMPose的肩髋中线独立测量：两模型同方向、各达到6度、相差不超过4度，且时间窗满足同样的可见性/持续条件；恢复带各4度。两模型不一致不新增结论，计数仍用原输入。先补“水平肩线但躯干侧倾”及“模型冲突不确认”测试，再回放，不针对视频编号设规则。

## 4. 已实现与原视频结果

- `body_lean.py`实现人体外长线的平行/透视方向参考；背景点KLT与RANSAC跟踪要求至少12个内点、内点比例≥80%、足够横纵分布、单次旋转/尺度受限。校准超过3000ms、跳帧超过250ms、几何改变或跟踪失败时拒判，不能永久沿用旧方向。
- `pretrained_input.py`根据原唯一人体的可见点自动提取人体框，再运行RTMPose并恢复原图坐标。没有改写原MediaPipe的`poses/world_poses`，没有按视频编号选择角度或预置问题。
- `PretrainedObserver`独立做同向时间窗中位数、两条确认路径与恢复带；当前缺证据立即撤回。保存具体左右侧与参考来源，`coaching.py`提高侧倾提示优先级，`skeleton.py`登记肩髋高亮。撤回项不携带伪造的`side=none`去阻止已有左右侧提示清理。
- 新增`FITNESS_BODY_LEAN=1`选择身体观察；不需开启全部`FITNESS_PRETRAINED_CORRECTION`，也不加载手部检测/RF候选。默认启动仍关闭；当前原8765本机预览使用同一恢复库单独开启身体观察，所有预训练候选总开关保持关闭。没有公网部署或改动私人数据/预算。

## 5. 当前纠错能力的准确说法

| 内容 | 当前接入 | 效果边界 |
| --- | --- | --- |
| 动作幅度不足 | 深蹲、俯卧撑、后撤弓步、弯举、开合跳、高抬腿等 | 可见关节/完整周期的参考检查；不等于各动作独立准确率达标 |
| 髋位/顶端对齐偏差 | 平板、俯卧撑的高低髋位，臀桥顶端肩髋膝对齐 | 机位、支撑状态、肩髋腿可见性受限时拒判 |
| 躯干借力、上臂摆动 | 普通/锤式弯举及部分器械动作 | 步骤58普通弯举独立粗标签10条bad中命中4条，6条good无误报；仍有漏检，不宣传全覆盖 |
| 双臂高度持续不一致 | 推胸、肩推、飞鸟等双侧动作 | 只看双侧同时动作的图像投影，不适用于主动单侧/交替练习 |
| 硬拉顶端伸展不足 | 顶端髋膝伸展参考 | 不能据此识别脊柱局部弓背、发力或适合个人的负重 |
| 推举起始肘腕对齐 | 杠铃过顶推举起始位的肘腕横向关系 | 只看可见起始姿态，不等于验证全程杠铃轨迹或腰部代偿 |
| 持续侧倾 | 本步器械推胸身体观察 | 本人1693/1694部分区间已真实命中并可见、可保存；不是独立人物≥70%验收 |
| 卧推握距/腰背等上游类别 | 三份RF已复现并有受控接口 | 默认关闭，只是原数据/接线验证，不算网站已可靠支持的真实错误类型 |
| 握持不当、拇指绕握、手掌与把手接触 | 尚未可靠实现 | 手指关键点或手指伸展不等于握法结论，当前不开放未验证的握持判断 |
