### 1.2 遇到冲突时怎样处理

优先级为：用户最新明确要求 → 有效业务、权限和数据约定 → 本文件明确的修正决策 → 对应已确定UI图 → 未确定的辅助图 → 历史页面和通用设计建议。

- 颜色气质、字体层级、边框、圆角、品牌、导航组件和主要内容顺序必须统一。
- 真实数据、权限、原视频可用性、保存状态和可访问性优先于图中的示例。
- 可以调整局部宽高、换行、按钮位置和折叠方式，解决长内容、窄屏或操作遮挡；不得借修正之名换主题、套另一套后台模板或重排整个训练流程。
- 修正已有缺陷不要求重新生成整页设计图。按本文件落实，并在实际验收记录中写明图稿差异、原因和结果。
- 新问题涉及业务目标、兼容性、真实数据、安全或费用且没有现成约定时，说明具体未决点；其他不受影响的工作继续。

本轮不训练模型、不改纠错阈值、不迁移真实个人数据库、不上传私人演示、不增加收费调用或额度、不部署、不改比赛冻结副本。只有展示或已有页面缺失的接线属于本轮；不能根据图中按钮推导出新的后台业务。

## 3 统一设计系统

### 3.1 色彩与对比度

颜色必须先集中成公共CSS变量，再由组件使用；不让每页自行再取一套近似颜色。

| 语义 | 起始值 | 使用规则 |
| --- | --- | --- |
| 页面背景 | `#FFF9F1` | 全站暖奶油底 |
| 主表面 | `#FFFCF8` | 表单、详情与弹窗 |
| 浅杏分区 | `#FFF0DF` | 选中、解释和重点区域 |
| 主文字 | `#402517` | 标题、正文、表单标签 |
| 辅助正文 | `#78675B` | 描述和帮助文字；原`#827369`只用于足够大或非必要装饰文字 |
| 品牌强调 | `#DE5926` | 标志、大标题强调、较大图形和选中标记 |
| 强调深色 | `#B9431C` | 小尺寸强调文字、实底主按钮底色及可读性不足的位置 |
| 浅边线 | `#EEDCCB` | 表面分隔，不单独承担输入框边界或焦点识别 |
| 控件边界 | `#9F8170` | 需要辨认的输入框、开关未选中态，可根据实测微调 |
| 正常／完成 | `#247B4B` | 同时配文字或图标 |
| 观察／提示 | `#8A6118` | 表示等待或证据不足，不能当偏差结论 |
| 危险／错误 | `#B53B2C` | 删除、字段错误、保存故障；不能与普通主按钮只靠颜色区分 |
| 可见骨架 | `#299F91` | 已保存轨迹的可见关节 |
| 骨架提示部位 | `#E9AA3B` | 与现有回放逻辑一致，必须有文字说明 |

对比计算示例：`#DE5926`与`#FFF9F1`约3.61:1，原辅助字`#827369`与该底色约4.36:1；`#B9431C`与底色约5.17:1，`#78675B`约5.16:1。这说明不能直接把品牌橙用于所有小字，或把奶油色小字放到任意橙底上。

本项目正文对比目标至少4.5:1，可辨认控件边界目标至少3:1；大字、禁用和装饰按实际用途分别检查，不以此表代替最终渲染检查。保持暖色风格，通过深浅层级修正可读性。

### 3.2 字体、尺寸和留白

- 中文使用项目已有系统字体栈，优先微软雅黑／苹方等可用无衬线字体，不为本轮引入远程字体。
- 正文默认16px，行高约1.6；辅助正文14px起；按钮与输入文字16px。重要状态不得缩成难读的小字。
- 页面一级标题桌面32～40px，窄屏26～30px；首页宣传标题桌面48～64px，窄屏32～40px。标题长时自然换行，不强行压缩字距。
- 共享页头桌面约80px高，主导航16px；常用控件48px高、小控件实际可点击区域至少44×44px；认证主按钮可用56px。
- 内容最大宽约1280～1320px，左右安全边距桌面24～40px、手机16px；间距以4／8／12／16／24／32／48px为基础。
- 控件圆角10～12px、业务卡片12～16px、照片16～20px；首页主入口可用胶囊。统一组件同尺寸，不照抄各生成图的细微随机差异。
- 卡片以浅底和细线分层，必要阴影只用轻暖棕投影；不得恢复厚重橙色阴影、霓虹发光或黑底大屏风格。

### 3.3 共享组件与行为

| 组件 | 统一要求 |
| --- | --- |
| 页头／导航 | 品牌左、导航整体居中、头像右；两侧宽度变化不能挤偏导航；公开认证页仅登录／注册入口 |
| 头像菜单 | 仅个人中心、设置、退出登录；管理员工具放设置内，权限由服务端判断 |
| 页内标签 | 概览／列表等统一下划线选中态与`aria-current`；不混用多套外观 |
| 返回 | 子页左上方，文字说明实际目的地；保留筛选、分页和来源，不把所有返回写死成首页 |
| 按钮 | 主、次、文字、危险、加载和禁用态齐全；一个操作区突出一个主要动作；图标不能替代必要名称 |
| 表单 | 可见标签、输入帮助、字段错误、提交中及成功／失败；不只在占位文字写标签 |
| 错误反馈 | 字段旁说明；提交失败时可聚焦的错误汇总链接到字段；输入内容保留，不在每次失焦时强抢焦点 |
| 加载 | 保留布局及当前筛选；已有结果更新时不先清空为大白屏；加载样式不伪造真实统计 |
| 空态 | 区分尚无记录、筛选无结果、资源不可用；只提供与当前原因对应的操作 |
| 弹窗 | 标题、关闭、明确操作、焦点约束与返回、背景滚动锁；长内容内部滚动，关闭后解除本层锁 |
| 危险操作 | 说明实际删除范围、保留内容和不可恢复性；默认焦点在取消；不能点完即显示伪成功 |
| 图表 | 数据来自接口，有文字摘要／可访问表格；缺样本显示原因，不补零或编造平滑趋势 |
| 来源与依据 | 默认收起，点击展开真实引用；不可用或旧来源显示失效状态，不保留装饰性假链接 |

**教练闭环。** 工具调用／必要澄清沿用现有任务状态；显示用户能理解的“正在整理依据／等待你确认／已完成”等文案。最多一次必要问题，不自行追加连续问卷。保存复测目标须用户点击确认，不因AI生成卡片而写入。

**引用。** 训练依据与公共知识分别展示，来源数量真实计算；已删除记录、旧修订或失效知识不继续引用。聊天和复盘不把模型输出当作视觉纠错真值。

**临时营养。** 保留“描述情况／填写信息”两入口、云端发送同意、本人相关历史同意，以及每日蛋白质／热量参考结果。纯表单确定性计算沿原本地接口；自然语言提取纳入现有教练预算。缺关键输入时不猜值，适用范围与来源由既有结果显示，不在本轮另设计公式。

**资料生命周期。** 本次描述的临时身体资料仍不自动保存，不写入URL或浏览器持久存储。最新用户要求：主动保存的本人健身档案由普通AI上下文及工具教练默认读取，不要求重复填写或额外勾选；仍仅在用户主动发送并通过原同意／调用流程时发给供应商。工具任务只把资料加入内存消息，不写进用量账本。修改或清除档案会使旧普通AI／教练上下文失效，防止旧回复恢复已清除资料。已保存的旧营养资料不自动覆盖健身档案。刷新、离开、退出及切换账号按创新升级契约清除临时内容，旧结果迟到不得恢复已删除资料。

## 6 关键状态及数据契约

### 6.1 实时与视频状态

| 领域 | 必须区分的状态 | 展示与操作 |
| --- | --- | --- |
| 相机 | 未开启、申请中、预览／分析、暂停、中断、结束 | 相机按钮／继续／结束随真实状态变化，不用多套互相冲突的按钮 |
| 实时结果 | 正在观察、具体偏差、该判项未见偏差、无法判断 | 观察不改写为正常；偏差带当前有效建议 |
| 自动保存 | 保存中、已保存、失败冻结、原操作待核对、已放弃未保存部分 | 重试原操作，不重新创建分析 |
| 视频 | 未选、就绪、排队／处理、取消中、完成、部分完成、失败 | 处理只显示正在观察；已完成与已保存分别呈现 |
| 修订 | 当前有效、重分析中、成功替代、失败保留旧版、取消 | 依据和关联AI结果同步当前有效修订 |
| 媒体 | 当前原片、原片待匹配、只有轨迹、未保存、过期、已删除 | 只提供实际可用的播放方式 |

### 6.2 AI与跨请求状态

必须区分未配置、可发送、提交中、排队、生成中、等待一次确认、停止中、完成、失败、额度不足、结果待核对、依据失效及过期。具体状态码从现有接口映射，不另造一个与服务端平行的假任务状态机。

每个响应须与当前用户、请求、会话、上下文或修订身份匹配。更换媒体、切换动作、关闭临时模式、退出账号和删除来源后，旧成功与旧失败都不能覆盖新状态。

写请求继续复用`app.js`的CSRF、`Idempotency-Key`、版本及`RequestError`处理。未知提交先核对原请求，不无限自动重试或静默切换系统／个人来源。

### 6.3 数量、单位与时间

- 动态周期、静态毫秒、源时间、片段局部时间和墙上日期分别命名；不能只因图里都显示“个”就统一单位。
- 源时间区间沿用`[start_ms, end_ms)`；播放器定位与骨架偏移按对应记录处理，不重复加减片段偏移。
- 偏差比例只在可评估分母有效时计算，显示舍入与后台一致；未知量单列。
- 复测结论来自现有可比契约；同一动作名称不足以证明同变式、同侧或同规则。
- 所有设计日期、用户名、消息、趋势和来源数量在运行时替换为真实值；缺数据时显示真实空态。
