# 比赛展示与答辩

本目录用于讨论和推进观动知姿的后续完善，当前优先比赛展示与答辩。交付材料继续放“比赛提交”，应用开发继续使用现有工程。

## 已确认的方向

- 赛项为AI WEB网页开发挑战赛，围绕智能运动指导场景展示。
- 对外材料聚焦已有功能、技术设计和实际操作，不加入无依据的准确率或训练成果。
- 代码仓库与作品文档使用项目名，学校、队员、老师和队名单独在赛事报名表填写。
- 视频分析中统一“正在观察”；完成后展示实际问题、时间段、建议和定位回看。
- 首页预处理展示不作为真实纠错能力证据，证明效果使用实际任务与保存结果。

## 展示主线

一句话介绍：观动知姿将训练画面转化为可定位、可回看、可解释的运动反馈，让使用者理解哪里需要调整、发生在什么时候、下一次怎样练习。

围绕一次训练完成“输入画面 → 分析进度 → 具体问题 → 定位回看 → AI解释或报告”，再补充实时训练和记录管理，不逐个念菜单。

## 六分钟演示安排

| 时间 | 展示内容 | 要让评委看到的事实 |
| --- | --- | --- |
| 0:00—0:35 | 问题与作品定位 | 自主训练难以将姿态问题对应到画面 |
| 0:35—1:10 | 实时准备与取景 | 输入清楚，能够选择动作与机位 |
| 1:10—2:50 | 视频分析与完成反馈 | 真实任务、问题和具体时间 |
| 2:50—3:35 | 点击问题定位回看 | 提示与原视频位置一致 |
| 3:35—4:30 | 记录、报告或AI解读 | 画面事实与训练记录连接 |
| 4:30—5:20 | 架构与技术重点 | 本地视觉、连续规则、来源与Web交互 |
| 5:20—6:00 | 手机适配与价值 | 同一流程适用于不同屏幕 |

这是按官方5—8分钟要求拟定的录制建议。耗时分析可保留真实开始和结束并明确标注加速或剪辑，不让剪辑造成实时性能误解。使用独立演示账号，避开姓名、邮箱、密钥、验证码及私人信息。

## 答辩问题与回答要点

### 为什么是AI应用

视觉模型从画面提取人体结构，连续规则结合时间与阶段形成观察，语言模型围绕训练证据解释结果。Web将这些能力组织为完整训练流程。

### 与普通播放器有什么区别

保存结构化问题、时间范围、部位与建议，从问题直接回到画面，并把结果纳入训练记录和AI上下文。

### 原创工作在哪里

媒体输入与坐标还原、连续观察、任务与保存状态、问题定位、来源版本、训练证据与AI上下文，以及统一的前端工作流。明确开源模型和框架来源，不将预训练模型称作从零独立训练。

### 如何证明能运行

现场完成真实任务并展示保存结果与视频位置；说明固定版本、资源SHA256和运行脚本。工程检查与真实运行结果分别介绍，不把测试数量当作模型准确率。

### 如何解释Git历史

比赛仓库从材料整理时建立真实提交，不补写日期；早期过程由既有开发文档和真实聊天保留。版本标签用于冻结评审代码，之后继续正常提交。

### 如何保护用户数据

本地视觉处理、服务端数据归属检查、密钥加密保存、运行资料不写Git。涉及第三方AI的素材按授权发送，演示使用可分享素材与独立账号。
